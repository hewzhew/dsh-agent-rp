# 可执行世界的叙事投影

可执行世界同时服务规则结算和连续故事，但两者不能共用一段结果摘要。规则模块拥有状态、合法动作和已经发生的事件；故事流水线只解释这些记录，不替规则模块掷骰、移动、改变回合或决定胜负。

## 为什么规则结果不能直接成为正文

“掷出 3”“前进到第 12 步”足以重放规则，却没有说明现场发生了什么变化、人物为什么需要回应、这段文字在整场戏中承担什么作用。写作 Worker 只有这些材料时，只能在机械事实外添加动作修饰，或者把每个结果换一种说法复述；更多文风指令不会创造缺失的戏剧材料。

成熟桌面角色扮演规则通常先把随机结果变成局势变化，再共同叙述画面。Blades in the Dark 的行动检定先确定人物目标、危险位置和预期效果，结果产生成功、减效、复杂状况、机会丢失或更危险的位置；进度钟只显示已经由虚构局势形成的进展或威胁，不反过来替代虚构。Ironsworn 的 move 只在行动危险或不确定时触发，弱成功和失败附带代价，特殊骰面会带来意外复杂状况或机会，oracle 提供可结合既有故事解释的细节。Fate 的 scene aspect 则把场景中值得人物利用或会使人物受阻的具体事实变成可操作对象。

这些机制的共同点不是特定骰制，而是下面的顺序：

```text
人物目标或世界动作
  → 权威规则结算
  → 现场变化、压力、机会或关系后果
  → 各人物按自身认知独立回应
  → Host 直接编排，或导演选择本轮节拍
  → 连续场景正文
```

## 模块接口

世界模块从一批已经记录的事件生成 `PlayWorldNarrativeProjection`。Host 在任何模型看到它之前验证事件引用和人物范围。

- `facts` 是正文必须尊重的公开事实。每项事实引用一个或多个本轮世界事件，并标为 `essential` 或 `compressible`：每位人物的首次起飞、碰撞、到达终点和事件牌等场景转折必须明确保留行动者、数值与结果，普通航线位移、后续起飞和无效投掷可以和同类机械事件合并成时间流动；两者都不能改变最终结果。
- `cues` 是当前事实打开的叙事方向，分为现场变化、压力、机会和关系后果。Cue 不是已经发生的人物行动；只有被列入 `characterIds` 的人物 Worker 可以选择回应，人物没有回应时正文不能把建议写成事实。
- `cadence` 决定事件批次是压缩过渡、完整场景节拍还是场景收束。过渡可以继续累积多个规则回合，到达安全上限后合并呈现；场景和收束立即进入写作流水线。
- `invariants` 是不要求写进正文、但任何叙述都不能违反的世界事实，例如场景只有一张棋盘、各回合共用一枚骰子。Host 校验稳定 id 和内容后把它们交给正文与编辑 Worker。

Host 在一句或相邻两句中核对 `essential` 事实的语义词组和全部数值，使正文可以把一次规则结果自然拆成动作连续的两句；只有同一局部无法恢复必要事实时才退回世界模块提供的事实文本，不能因为整段正文采用了不同句法就覆盖已经合格的场景。

需要跨回合保留的选择不能只写成 cue。世界模块另以 `characterOpportunities` 投影当前人物拥有的未决机会；每项机会保存稳定 id、来源事件、所有者、可回应人物、使用条件及 `available` 或 `retained` 状态。人物 Worker 必须结构化选择使用、保留或放弃，Host 只把最终公开正文中确实存在所需台词的使用决定交回模块。人物世界投影继续显示本人机会的 `used` 或 `declined` 终态，但终态不会重新进入可处置列表。机会处置与故事事件在一次工作区保存中提交；声音审校拒绝台词、正文遗漏台词或流水线中断都不会消耗机会。其他人物只能看到公开的来源事件，不能读取所有者的机会状态。

叙事投影必须能从持久化世界事件重建。随机出现的风、访客、故障或事件牌如果改变现场，世界模块要先把它记录为事件；不能只在临时 prompt 中告诉模型。这样重试、重启、人物认知投影和最终历史引用同一事实来源。

## 人物和正文

人物 Worker 继续只接收人物档案、该人物可见的事实、获准历史和世界投影。`cadence` 只控制正文篇幅，不授予人物公开反应；存在该人物可回应的 cue 时，人物才可以提出一个已经由当前处境引起的非规则行动或对白意图。公开行动必须已经完成并在没有对白时仍留下可观察结果；目光、姿态和等待接话不单独构成行动。掷骰、移动棋子和其他规则动作仍只能从 Host 公布的稳定动作 id 中选择。

导演只接收公开事实、cue、人物公开行动和结构化说话意图，不接收人物观察或私有洞察。它可以省略没有信息增长的回应，不能把并行人物提案伪造成彼此听见后的连续问答。没有故事图或伏笔义务且只启用一个正文分区的自动世界回合由 Host 直接编排公开行动和至多一个说话意图，不调用没有决策空间的导演。正文 Worker 和最终编辑除写作材料外还接收 Host 汇总的校验材料，其中保留事实的事件序号与保留方式、逐条事件数值、世界不变量、获准人物行动、未获准新增行动的人物和逐字对白；重复事件不能被误写成多个物体，不同结果不能被概括为相同，未获准的具名人物行为必须删除。正文或编辑若吞掉一项 `essential` 事实或其中的数值，Host 保留上一份完整草稿；连续无效投掷等 `compressible` 事实仍可自然合并。

## 飞行棋纵切片

第一方飞行棋把以下结果标为完整场景：棋局开场、第一架飞机起飞、棋子碰撞、飞机到达终点和棋局结束。普通移动属于可累积的过渡。开场和首次起飞只改变呈现节奏，不自动产生人物 cue；碰撞、事件牌和终局带来实际选择或关系后果时才开放人物回应。

内置飞行棋世界资源带有两张结构化事件牌。连续四个角色回合都没有飞机起飞时，规则模块记录风掀起棋盘一角、基地木机随之晃动，只让触发本轮的行动人物决定如何压稳棋盘。第一架木机停在航线第 8 步时，格子下的折签公开一次可使用、保留或放弃的提问机会；模块从这项来源事件建立行动人物专属的持久机会，对手要等问题通过声音审校并实际出现在正文后才获得回答前提。旧棋局若已经记录折签事件但还没有机会字段，模块按事件 id 和所有者恢复同一个稳定机会，不重新触发事件牌。事件牌把触发条件、事实标题与摘要、cue 类型、可回应范围、持久机会的使用方式及是否重复分别保存；事件保存在世界日志中，所以重试和重启不会重新抽取或改变现场。

当前场地编辑器以卡片形式编辑这些字段，保存时由 Host 用场地 revision 检查并让规则模块重新验证配置；当前棋局状态和既有事件保持不变。飞行棋事件牌支持连续无合法移动、棋子停在指定航线步数、发生碰撞和行动人物达到指定终点棋子数四种触发条件；回应范围支持触发人物、其他棋手或所有在场人物。触发者来自引发事件的权威日志，不使用结算后可能已经切换的当前行动者。后续要让回应范围支持指定人物槽位，并让故事地图节点也能约束事件牌。事件牌必须引入新的选择、信息、资源变化或关系后果；只提供天气、目光和手势等装饰不构成有效 cue。

## 验收

- 四个连续无效回合只产生一个可发展的场景压力，不生成四段点数播报。
- 世界事实和 cue 都引用真实事件序号；未知序号或未知人物在进入模型前被拒绝。
- 世界不变量拥有稳定且不重复的 id；正文和编辑能区分事件次数、事件数值与物体数量。
- 同一事件对每个人物的输入按 `characterIds` 和人物认知过滤，不能借导演信息补全。
- 导演输入不含人物观察与私有洞察；私有变化只进入所属人物的持久分区。
- 人物没有提出公开反应时，导演和正文不能把 cue 当作已经发生的动作。
- 第一架起飞、碰撞和终局能够结束过渡累积并形成新的场景节拍；只有后两者自动授权人物回应。
- 第一架起飞必须同时呈现促成起飞的骰点和棋子离开基地后的落点，不能只展示结算后的棋盘快照。
- 重试与重启重放同一世界事件，不重复抽取事件牌或改变现场事实。
- 落格、碰撞和终点进度事件只由本次规则结算触发；编辑配置不会回溯旧日志补抽事件牌。
- 正文只有事件牌实际授权的人物可以新增行动；其他人物可以承担已记录的规则动作或获准对白，不能被补写目光、表情、姿态或停顿。
- 未决机会只进入所有者的人物投影；保留后会在所有者后续获准回应的回合重新出现，明确放弃后不再出现。
- 提问机会只有在目标人物和最终可见问题都存在时才能变为已使用；候选台词被审校拒绝时保持原状态，对手在问题公开前没有回答前提。
