# 故事工作室与多人物写作流水线

故事工作室把长期剧情保存为类型化故事图、人物事实、事件、资料和有序输出分区，并在被角色会话选中后启用固定顺序的多 Worker 写作流水线。它用于同一篇故事里的多人物认知与分区正文，不创建多个并列的顶层聊天 Agent，也不替代角色卡、世界书或普通会话历史。产品方向与反馈判断记录在 [故事工作室设计](story-studio-design.md)。

## 使用入口与界面

从 Agent RP 工作台打开「故事工作室」。顶部用于选择或新建故事；桌面端左栏在故事地图、事件时间线、人物、资料和输出布局之间导航，右侧属性面板编辑当前对象；Worker provider、model 和并发数位于设置抽屉。窄屏改用顶部横向视图入口，属性面板可独立打开和关闭。

故事地图由 `@xyflow/react` 提供平移、缩放、连线、节点拖动、Controls 和 MiniMap。画布承载篇章、剧情、秘密及先后、因果、属于、埋设与回收等有语义关系；资料依据使用关联剧情节点或人物事实的独立引用，时间线、资料和输出分区使用各自适合的列表或卡片视图，不强塞进一张画布。

AI 连续性建议以候选节点和候选关系呈现。候选内容只有在玩家接受后才变为正式故事数据；关系两端必须先成为正式节点，才能接受关系。拒绝候选节点会同时移除指向它的候选关系，拒绝候选关系只移除该关系；正式图与候选图在生命周期、样式和模型输入中保持分离。人物页的中央认知矩阵以事实为行、人物为列编辑知情范围；人物卡打开 Persona、人物视角和下一轮 Worker 输入预览。事件来源事实可以进入对应时间线，事件属性面板也会列出由它形成的事实。

## 文件与保存

故事默认保存在 `~/.dsh/agent-rp/story-workspaces/<story-id>/`：

```text
story.json
nodes/<node-id>.md
characters/<character-id>/persona.md
outputs/<output-id>.md
sources/<source-id>.md
```

`story.json` 保存格式版本、工程信息、revision、节点与关系索引、人物事实、事件、输出顺序、资料索引、引用、研究收件箱及流水线设置。较长正文分别存入节点、Persona、输出说明和资料 Markdown。保存使用 revision 检查，页面基于旧 revision 提交时会明确拒绝覆盖较新的编辑；文件写入使用同目录临时文件替换，所有标识经过校验，不能逃逸工程目录。

格式 0 工程首次读取时一次性迁移为格式 1。旧大纲、伏笔、提案、历史、人物知识、分区和资料会转成对应的类型化对象；旧回合 marker 会在迁移入口清除。迁移完成后删除已经被替代的格式 0 文件，不长期维护两套创作模型。

## 故事对象

- **节点**分为篇章、剧情和秘密，记录标题、状态、正式或候选生命周期、导演或公开可见范围、画布位置、正文、参与人物和可选来源事件。
- **关系**分为先后、因果、属于、埋设与回收，连接两个节点；伏笔关系另外记录未埋设、已埋设、已触发、已回收或已放弃状态。
- **人物事实**记录文本、确认状态、知情人物集合、可见范围及手工或事件证据来源。中央认知矩阵直接编辑 `knownBy`，它是人物 Worker 可读取事实的唯一权威。
- **事件**来自真正展示给玩家的最终回复，记录回合、摘要、最终正文证据、参与人物和可选剧情节点。参与事件不自动使人物知道事件内容；只有事件派生事实的 `knownBy` 授予人物 Worker 读取权。
- **资料**分为原著、参考、研究和网络资料，保存名称、启用状态与唯一一份可编辑正文；阅读器依据 Markdown 标题和自然段生成有界段落。
- **引用**保存资料标识、段落位置、原文快照、说明和可选剧情节点或人物事实。原文改变不会改写旧快照；剧情引用进入导演输入，人物事实引用只进入能够读取该事实的人物 Worker。
- **研究收件箱项目**来自实际完成回合使用过的网络搜索结果，保存 URL、查询、标题、摘要、Session、回合与结果事件序号。它在玩家收为研究资料之前不参与模型输入；收下后，正式资料继续保留同一组网络来源信息。
- **输出卡**分为正文、人物和历史，记录名称、职责、启用状态和可选目标人物。顺序可以拖动，也可以用上下按钮调整；保存后的顺序就是分区生成和展示顺序。

## 认知范围

每个阶段只接收完成本职工作所需的资料：

| 阶段 | 可以读取 | 不直接读取 |
|---|---|---|
| 研究 | 公开事件、最近会话、相关本地资料、网络检索结果、当前玩家输入 | 人物私有事实、未来正文草稿 |
| 人物 | 该人物 Persona、`knownBy` 包含该人物且未被否定的事实、当前玩家输入 | 其他人物事实、导演故事图、候选节点、未公开未来安排 |
| 导演 | 正式故事节点与关系、未回收伏笔、公开事件、研究简报、各人物独立提案、输出定义、当前玩家输入 | 人物事实记录原文 |
| 分区 | 对应输出说明、导演方案、当前玩家输入 | 其他分区草稿与工作区原始数据 |
| 编辑 | 按输出卡顺序排列的分区草稿 | 故事工作区原始数据与人物私有事实 |
| 连续性 | 最终可见正文、当前正式故事图、当前场景参与人物 | 没有进入最终正文的内部草稿 |

当前场景节点的 `participantIds` 决定哪些人物 Worker 参与；没有活动节点时暂时让全部人物参与。人物上下文由结构化事实即时编译，不依赖不可追溯的累计知识文本。导演可以综合人物提案安排事件，但角色 Worker 本身不会因导演拥有全局资料而获得其他人物的知识。

## 回合顺序

故事工作室只在 Agent 模式的第一步准备正文：

1. 本地检索从启用的原著、参考和研究资料中选出与当前输入和近期会话相关的有界片段，并自动附带命中位置前后的段落；`web` 资料只声明可用的网络查询范围，不伪装成本地事实。
2. 研究 Worker 把结论分为明确事实与不确定项，每条明确事实必须引用输入中的事件、会话或资料段落编号。证据不足时，它可以请求最多两条本地或网络追加查询；运行器去重查询、附加新证据并再次调用研究 Worker，直到得到完整简报、没有新证据或达到 `researchMaxPasses`。
3. 当前场景人物 Worker 分别依据自己的 Persona 和事实提出行动；同阶段最多并行 `maxParallel` 个请求。
4. 导演 Worker 根据正式故事图、未回收伏笔、研究简报和人物提案制定本轮方案。
5. 启用的输出分区分别写作；同阶段并行度同样受 `maxParallel` 限制。
6. 编辑 Worker 删除复读、八股句式和正文外解释，同时保留事实、对白归属、视角、标题、顺序与分区职责。
7. 顶层角色 Agent 收到编辑后的草稿，只能为角色口吻和既有格式做局部适配，再产生玩家可见回复。
8. 原有正文审阅与状态结算完成后，连续性 Worker 读取最终可见正文并沉淀事件、人物事实以及类型化候选节点和关系；本轮实际使用过的有效 HTTP(S) 网络结果同时进入研究收件箱，相同 URL 不重复追加。

阶段顺序固定；只有同阶段人物和同阶段分区可以并行。`maxParallel` 默认为 4，可设为 1–8。`researchMaxPasses` 默认为 2，可设为 1–4；一轮表示只读取首批本地证据，两轮允许一次主动追查。故事 Worker 默认跟随当前会话模型，也可以为整个故事流水线指定独立 provider 和 model；该设置不改变顶层角色 Agent 的模型。

故事流水线失败时按最近可用结果降级：研究输出无法解析时停止追查并保留上一轮有效简报，没有有效简报时直接把带编号的首批证据交给导演；网络失败只移除该次网络结果。单个人物或分区失败时忽略该项，导演失败时使用输入资料组成有界后备方案，编辑失败时保留分区草稿。整个准备阶段异常时，顶层角色 Agent 仍按普通角色流程运行。连续性结果无法解析时，只把最终可见正文保存为事件，不猜测人物观察或剧情建议。

## 回合沉淀与重放

连续性 Worker 使用实际展示给玩家的回复，而不是导演方案或编辑前草稿。每个完成回合形成带最终正文证据的事件；只有正文中明确亲历或可感知的内容才会成为对应人物事实。剧情建议生成带类型、标题、正文和参与人物的候选节点；先后、因果、所属和伏笔建议生成候选关系，可以连接既有正式节点或同一批候选节点。候选对象不会直接进入正式故事图。同一回合使用稳定 key，重试不会重复沉淀。

网络搜索结果与正式资料采用同样的候选分层：搜索摘要可以供当轮研究 Worker 判断，但完成回合后只进入收件箱。玩家选择“收为资料”才会建立可编辑、可检索和可引用的研究资料；“忽略”只移除候选。接受时保留原始 URL、查询和 Session 事件位置，因此后续编辑摘录不会抹掉来源。

故事阶段的完整模型请求和成功文本或稳定失败分别写入 `agent-rp/story-stage-request` 与 `agent-rp/story-stage-result`；网络检索、最终准备稿和回合沉淀也各自写入可忽略的 Session 事件。相同 turn、step、故事及 revision 的准备稿可以从 Session 重放复用，导出、分支与重载不依赖进程内缓存。

## 当前实现边界

当前纵切片已经覆盖格式 1 存储、故事图、事件时间线、人物认知矩阵与 Worker 输入预览、事件来源双向核对、资料阅读器、章节与段落定位、相邻原文自动展开、可关联剧情或人物事实的引用、研究 Worker 主动发起的本地与网络有界追查、网络研究收件箱、输出排序、候选节点与候选关系，以及既有多 Worker 流水线。底部阶段条尚未接入实时阶段进度；人物事实的事件观察编辑、时间线与故事图的直接联动也仍需继续深化。这些是后续迭代项，不应通过恢复大文本框或把所有对象放入故事图来绕过。
