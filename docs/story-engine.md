# 游玩场地与多人物写作流水线

游玩场地把可执行世界、长期剧情、人物事实、事件、资料和有序输出分区组合在一起，并在被角色会话选中后启用固定顺序的多 Worker 写作流水线。角色卡提供稳定身份，本局人物实例保存角色卡快照、私有认知和临时状态；普通世界书继续提供提示词资料，可执行世界模块另外拥有类型化状态、动作、事件及人物和导演投影。产品方向与反馈判断记录在 [故事工作室设计](story-studio-design.md)。

## 使用入口与界面

从 Agent RP 工作台打开「游玩场地」。顶部用于选择或新建场地；桌面端左栏在世界、故事地图、事件时间线、人物、资料和输出布局之间导航，右侧属性面板只在选择对象时出现；Worker provider、model 和并发数位于设置抽屉。窄屏改用顶部横向视图入口，属性面板可独立打开和关闭。

场地页列出 Host 已安装的世界模块。装入世界后，模块的原生视图直接读取权威状态，并把玩家亲自执行的掷骰、移动等操作提交到独立动作端点；普通整场地保存不能改写世界状态。会话继续时，模块另外只向当前人物 Worker 提供此刻合法的稳定动作 id，模型不能构造任意动作；Host 解析所选 id、执行规则并把幂等收据与新世界状态一起保存，同一 Session 回合重试不会重复掷骰或移动。当前第一方「幻想乡飞行棋」模块支持两至四位人物、四枚棋子、24 格航线、Host 掷骰、起飞、碰撞、到达、胜负、重新开局和持久化世界事件。人物可以绑定资源中心里的角色卡；绑定保存角色引用以及描述、性格、入场情境、示例对话和高级指令快照，也可解除绑定并继续作为手写人物设定。本局位置、状态、目标和备注属于人物实例，不会写回可复用角色卡。空白会话可以直接从已经装入世界的场地开始，不再要求额外选择一本普通世界书。

故事地图由 `@xyflow/react` 提供平移、缩放、连线、节点拖动、Controls 和 MiniMap。顶层画布承载可折叠故事簇以及先后、因果、埋设与回收等有语义关系；簇内场景、秘密和人物事实默认折叠为摘要，展开后可以直接选择内部节点。资料依据使用关联剧情节点或人物事实的独立引用，时间线、资料和输出分区使用各自适合的列表或卡片视图，不强塞进一张画布。完成的正文事件只记录它实际表现过的世界事件序号；时间线用这些引用展开规则来源，未进入正文的世界事件单独标出，点数、棋子位置和结算文本始终只由世界模块保存。

AI 连续性建议以候选节点和候选关系呈现。候选内容只有在玩家接受后才变为正式故事数据；关系两端必须先成为正式节点，才能接受关系。拒绝候选节点会同时移除指向它的候选关系，拒绝候选关系只移除该关系；正式图与候选图在生命周期、样式和模型输入中保持分离。每个故事簇可以规定内部信息默认无人知道、由场景参与人物知道、由指定人物知道或继承上级策略；人物页按当前人物汇合档案、场地状态、认知和经历，单条事实仍可继承故事簇策略或使用精确覆盖。全局人物乘事实矩阵只保留在 Agent 输入中的高级认知审计，不再占据人物主界面。人物视角、认知计数和 Worker 输入都从同一有效认知结果投影。

## 文件与保存

故事默认保存在 `~/.dsh/agent-rp/story-workspaces/<story-id>/`：

```text
story.json
nodes/<node-id>.md
characters/<character-id>/description.md
characters/<character-id>/personality.md
characters/<character-id>/scenario.md
characters/<character-id>/example-dialogue.md
characters/<character-id>/system-prompt.md
characters/<character-id>/post-history-instructions.md
outputs/<output-id>.md
sources/<source-id>.md
```

`story.json` 保存格式版本、工程信息、revision、节点与关系索引、人物场地状态、人物事实、事件、输出顺序、资料索引、引用、研究收件箱及流水线设置。较长正文分别存入节点、人物档案、输出说明和资料 Markdown。保存使用 revision 检查，页面基于旧 revision 提交时会明确拒绝覆盖较新的编辑；文件写入使用同目录临时文件替换，所有标识经过校验，不能逃逸工程目录。

`story.json` 也保存可选的世界模块快照。模块注册表负责创建、解析、执行动作，分别编译人物和导演投影，并把本轮权威事件投影成不可丢失的最小叙事首段；世界动作和场地表单共用 revision，因此旧页面不能覆盖新棋局。世界事件连续编号并计入场地大小限制。Session 从场地启动时写入可重放的选择事件和一段无模型正文的完整开场回合；DSH 因此把它视为已经开始的会话，下一次新建会话不会错误复用它。

格式 0 或格式 1 工程首次读取时一次性迁移为格式 2。格式 0 的大纲、伏笔、提案、历史、人物知识、分区和资料会转成对应的类型化对象；格式 1 的“属于”关系会转成节点父级，场景获得参与人物认知策略，既有人物事实保留原来的精确知情范围。旧回合 marker 会在格式 0 迁移入口清除，迁移结果立即写回，不长期维护多套创作模型。

## 故事对象

- **节点**分为篇章、场景和秘密，记录父级故事簇、折叠摘要、状态、正式或候选生命周期、导演或公开创作范围、画布位置、正文、参与人物、默认认知策略和可选来源事件。
- **关系**分为先后、因果、埋设与回收，连接两个节点；伏笔关系另外记录未埋设、已埋设、已触发、已回收或已放弃状态。故事簇所属只由节点 `parentId` 表达，不再同时保存一条“属于”关系。
- **人物事实**记录所属故事节点、文本、确认状态、创作范围及手工或事件证据来源。事实可以继承故事簇的认知策略，也可以用 `knownBy` 精确覆盖；两者计算出的有效知情人物是人物 Worker、人物视角和认知矩阵的共同输入。
- **事件**来自真正展示给玩家的最终回复，记录回合、摘要、最终正文证据、参与人物和可选剧情节点。参与事件本身不自动授予知识；只有故事簇明确选择“场景参与人物”策略，或事件派生事实明确覆盖知情人物时，人物 Worker 才能读取对应事实。
- **资料**分为原著、参考、研究和网络资料，保存名称、启用状态与唯一一份可编辑正文；阅读器依据 Markdown 标题和自然段生成有界段落。
- **引用**保存资料标识、段落位置、原文快照、说明和可选剧情节点或人物事实。原文改变不会改写旧快照；剧情引用进入导演输入，人物事实引用只进入能够读取该事实的人物 Worker。
- **研究收件箱项目**来自实际完成回合使用过的网络搜索结果，保存 URL、查询、标题、摘要、Session、回合与结果事件序号。它在玩家收为研究资料之前不参与模型输入；收下后，正式资料继续保留同一组网络来源信息。
- **输出卡**分为正文、人物和历史，记录名称、职责、启用状态和可选目标人物。顺序可以拖动，也可以用上下按钮调整；保存后的顺序就是分区生成和展示顺序。

## 认知范围

每个阶段只接收完成本职工作所需的资料：

| 阶段 | 可以读取 | 不直接读取 |
|---|---|---|
| 研究 | 公开事件、最近会话、相关本地资料、网络检索结果、当前玩家输入 | 人物私有事实、未来正文草稿 |
| 人物 | 该人物档案、本局状态、有效知情范围包含该人物且未被否定的事实、该世界模块为此人物生成的可见状态与事件投影、当前玩家输入 | 其他人物事实、世界私有状态及其他人物专属投影、导演故事图、候选节点、未公开未来安排 |
| 导演 | 权威世界投影、正式故事节点与关系、未回收伏笔、公开事件、研究简报、各人物独立提案、输出定义、当前玩家输入 | 人物事实记录原文 |
| 分区 | 对应输出说明、导演方案、当前玩家输入 | 其他分区草稿与工作区原始数据 |
| 编辑 | 按输出卡顺序排列的分区草稿 | 故事工作区原始数据与人物私有事实 |
| 连续性 | 最终可见正文、当前正式故事图、当前场景参与人物 | 没有进入最终正文的内部草稿 |

当前场景节点的 `participantIds` 决定哪些人物 Worker 参与；没有活动节点时暂时让全部人物参与。人物上下文由结构化事实即时编译，不依赖不可追溯的累计知识文本。导演可以综合人物提案安排事件，但角色 Worker 本身不会因导演拥有全局资料而获得其他人物的知识。

## 回合顺序

故事工作室只在 Agent 模式的第一步准备正文：

1. 可执行世界存在当前人物回合时，世界行动 Worker 只读取该人物档案、有效认知、人物世界投影和玩家输入，从模块列出的合法动作中选择；Host 完成一个规则回合并持久化动作收据与新事件。没有可执行世界或世界已经结束时省略此阶段。
2. 本地检索从启用的原著、参考和研究资料中选出与当前输入和正式故事历史相关的有界片段，并自动附带命中位置前后的段落；`web` 资料只声明可用的网络查询范围，不伪装成本地事实。
3. 研究 Worker 先读取当前权威世界状态、本轮刚完成的世界结算和按时间累积的公开历史，再把结论分为明确事实与不确定项；旧历史不能覆盖当前世界状态。每条明确事实必须引用输入中的事件或资料段落编号。证据不足时，它可以请求最多两条本地或网络追加查询；运行器去重查询、附加新证据并再次调用研究 Worker，直到得到完整简报、没有新证据或达到 `researchMaxPasses`。
4. 当前场景人物 Worker 分别依据自己的档案、本局状态和事实，对刚结算的世界事件提出反应与后续意图；同阶段最多并行 `maxParallel` 个请求。
5. 导演 Worker 根据正式故事图、未回收伏笔、研究简报和人物提案制定本轮方案。
6. 对白 Worker 使用按说话人拆开的原作证据起草逐字对白：目标人物原句校准声音，对手原句只提供接话上下文，语气分析单独标出。严格审校只能原样批准或拒绝，全部拒绝时至多重写一次并再次审校；拒绝状态随导演方案传给分区写作，依赖未获准对白的发话铺垫不会留下空壳动作。
7. 世界模块先把本轮事件投影成确定性的正文首段；启用的输出分区只补充确有信息增量的反应与获准对白，同阶段并行度受 `maxParallel` 限制。所有人物都没有非规则行动且没有对白通过审校时，运行器直接跳过正文 Worker，只保留权威首段。
8. 编辑 Worker 逐字保留世界首段，删除对它的复述、八股句式、正文外解释和未获对白审校批准的句子，同时保持分区职责；最终组装还会重新校验首段没有被模型删除。
9. 顶层角色 Agent 收到编辑后的草稿，只能原样返回玩家可见正文。
10. 原有正文审阅与状态结算完成后，连续性 Worker 读取最终可见正文，按正文明确发生的变化更新人物位置、状态、目标和本局备注，并沉淀事件、人物事实以及类型化候选节点和关系；若最终可见内容与 Host 生成的纯世界正文完全一致，则直接用世界事件确定性沉淀，不调用连续性模型，也不重复生成世界事实。本轮实际使用过的有效 HTTP(S) 网络结果同时进入研究收件箱，相同 URL 不重复追加。

阶段顺序固定；只有同阶段人物和同阶段分区可以并行。`maxParallel` 默认为 4，可设为 1–8。`researchMaxPasses` 默认为 2，可设为 1–4；一轮表示只读取首批本地证据，两轮允许一次主动追查。故事 Worker 默认跟随当前会话模型，也可以为整个故事流水线指定独立 provider 和 model；该设置不改变顶层角色 Agent 的模型。

故事流水线失败时按最近可用结果降级：研究输出无法解析时停止追查并保留上一轮有效简报，没有有效简报时直接把带编号的首批证据交给导演；网络失败只移除该次网络结果。单个人物或分区失败时忽略该项，导演失败时使用输入资料组成有界后备方案，编辑失败时保留分区草稿。整个准备阶段异常时，顶层角色 Agent 仍按普通角色流程运行。连续性结果无法解析时，只把最终可见正文保存为事件，不猜测人物观察或剧情建议。

## 回合沉淀与重放

连续性 Worker 使用实际展示给玩家的回复，而不是导演方案或编辑前草稿。每个完成回合形成带最终正文证据的事件，并产生一份包含人物状态、事实、节点和关系的类型化变更集；未在正文中明确变化的人物状态字段保持不变，相同文本的多人观察合并为一条事实及完整知情人物集合。候选节点同时携带折叠摘要、父级故事簇、参与人物和默认认知策略；先后、因果和伏笔建议生成候选关系，可以连接既有正式节点或同一批候选节点。候选对象不会直接进入正式故事图。同一回合使用稳定 key，重试不会重复沉淀。

网络搜索结果与正式资料采用同样的候选分层：搜索摘要可以供当轮研究 Worker 判断，但完成回合后只进入收件箱。玩家选择“收为资料”才会建立可编辑、可检索和可引用的研究资料；“忽略”只移除候选。接受时保留原始 URL、查询和 Session 事件位置，因此后续编辑摘录不会抹掉来源。

故事阶段的完整模型请求和成功文本或稳定失败分别写入 `agent-rp/story-stage-request` 与 `agent-rp/story-stage-result`；网络检索、最终准备稿和回合沉淀也各自写入可忽略的 Session 事件。相同 turn、step、故事及 revision 的准备稿可以从 Session 重放复用，导出、分支与重载不依赖进程内缓存。

## 当前实现边界

当前纵切片已经覆盖格式 2 存储与旧格式迁移、可执行世界注册与玩家动作通道、人物 Worker 的结构化世界动作、世界事件到正文时间线的引用、第一方飞行棋、角色卡绑定、场地直接启动、人物与导演世界投影、可折叠故事簇、故事图、事件时间线、继承与覆盖式人物认知、人物视角与 Worker 输入预览、事件来源双向核对、资料阅读器、研究收件箱、输出排序、连续性 Agent 统一类型化变更集、候选变更组的整组接受或拒绝，以及带原作语气证据和严格对白审校的多 Worker 流水线。让第三方模块注册原生客户端视图仍需后续接入。底部阶段条尚未接入实时阶段进度；时间线按篇章或场景聚合、从事件直接创建补充事实仍需继续深化。这些是后续迭代项，不应通过恢复大文本框或把所有对象放入故事图来绕过。
